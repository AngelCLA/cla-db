What the fork changes, exactly.

A minimal fork keeps the RxDB codebase intact. The delta surface is small, marked, and documented.

No collection cap

The artificial non-premium collection limit is removed. The verification suite proves 14, 20, 50, and 100 collections work.

Full API compatibility

Same public RxDB APIs, same reactive queries, same replication engine. Your existing RxDB code moves unchanged.

On-disk compatibility

Storage format stays aligned with RxDB 17, so existing databases keep working across the fork.

Dual ESM/CJS

TypeScript declarations and dual exports, verified by an external npm pack consumer test.

Marked deltas

Every fork modification is isolated and marked with // CLA-DB: comments, so upstream merges stay clean.

Apache 2.0

No proprietary plugins, no falsified license flags. Future adapters arrive as independent packages.

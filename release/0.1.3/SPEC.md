# CLA DB 0.1.3 Technical Specification

## Exploration and proposal

Start from protected master `94383e9432519afb46f0185e35fb48238a7167f2`. npm returns `@clatech/db@0.1.2` as latest, `0.1.1` and `rxdb@17.6.0` are available, and `0.1.3` is unpublished. [Core CI at the baseline](https://github.com/AngelCLA/cla-db/actions/runs/45832442960) succeeded. The [staging run](https://github.com/AngelCLA/cla-db/actions/runs/45837219576) passed the build and failed with `ENEEDAUTH`. The immutable-subject exchange failure documented by [npm/cli#9969](https://github.com/npm/cli/issues/9969) matches previous investigation; the issue is open and 0.1.2 was manually published with 2FA. Do not weaken the workflow or treat the manual publish as successful OIDC.

Extend [0.1.2's consumer, storage and package verification](../0.1.2/TESTS.md) instead of replacing it. Keep runtime changes outside `src/` unless a reproduced package regression proves one is necessary. Maintain npm as the core's installer. One canonical package, one tarball per compatibility run, one SHA-256 identity. Keep all 56 exports, the package allowlist, licensing, RxJS, open collection and resource tracking, Premium logic and storage version `17.6.0` unchanged. Do not change `engines.node`, website deployment, external settings, or archived release files.

### Version and API references

- [Node.js release schedule](https://nodejs.org/en/about/previous-releases): 20 is EOL, 22/24/26 are LTS as of 2026-11-26. This is upstream status, not a CLA DB result. [Vite baseline](https://vite.dev/guide/) is Node 20.19+ or 22.12+, so it is not part of the Node 20.0.0 floor smoke.
- [pnpm tarballs](https://pnpm.io/cli/add), [Bun tarballs](https://bun.sh/docs/pm/cli/add), [Yarn linkers](https://yarnpkg.com/features/linkers), [Deno npm and scoped permissions](https://docs.deno.com/runtime/fundamentals/node/), [TypeScript resolution](https://www.typescriptlang.org/tsconfig/moduleResolution.html).
- [Playwright browser builds](https://playwright.dev/docs/browsers) are coupled to the runner; [persistent context](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context) takes an isolated profile directory. Close the context and reopen it with the same directory; keep the server alive.
- [npm staged publishing](https://docs.npmjs.com/staged-publishing/) requires Node >=22.14.0/npm >=11.15.0 and a distinct 2FA approval. [Trusted Publishing](https://docs.npmjs.com/trusted-publishers/) needs an exact workflow, repository and environment on a supported runner. Leave `publish.yml`, `npm-release`, OIDC, SHA-256, protected-master guard and provenance in place.
- Initial exact tool pins: npm 11.19.1 (compatible Node), pnpm 11.23.0, Bun 1.3.14, Yarn 4.19.0, Deno 2.8.3, Playwright 1.65.1, Vite 8.4.0, TypeScript 6.0.3 (existing project pin), React 19.3.1. Use exact additional fixture dependencies consistent with the existing tooling; verify availability and record actual versions.

## Phases

1. Audit precedents and validate registry, CI and current tool docs. Document this design and the task mappings.
2. Implement version alignment, the package/runtime consumers and native browser integration in isolated edit surfaces. Verify deterministic behavior changes test first.
3. Link sequential compatibility and CI, preserve publishing guards, and update website/docs. Commit cohesive local units of roughly 400 authored lines where practical; no PR delivery is in scope.
4. Build the exact candidate once, run local/available checks, attach tarball/hash, audit and reports. If evidence is missing, classify it and do not call the candidate ready. Hosted verification of the new branch and publication require separate authorization.
